# claude-tooling

Готовая обвязка для [Claude Code](https://claude.com/claude-code): правила, агенты, скиллы и
хуки, которые помогают Claude не забывать между сессиями то, что он уже узнал о проекте и о
том, как вы работаете.

## Что это даёт

- **Знания не теряются.** Claude сам раскладывает узнанное по местам: мелочи и ваши поправки —
  в память, устройство проекта — в вики проекта, ход работы над задачей — в документ задачи. В
  начале следующей задачи он сначала читает это, а не заново ищет по коду.
- **Набор агентов и команд для проекта:** `/commit`, `/check`, `/diff-review`, `/unit-tests`,
  `/orchestrate` (план → исполнение → проверка), `/save-task-context`, `/update-wiki`; агенты
  для расследования багов, ревью, проверки регрессий. Шаблон не привязан к стеку — Claude
  подстраивает его под ваш проект при подключении.
- **Репозиторий проекта остаётся чистым.** Всё это лежит в отдельной папке данных и попадает в
  проект симлинками, которые git проекта не видит. Командный `CLAUDE.md`, если он есть, не
  трогается.
- **Обвязка улучшается со временем.** `/tooling-review` читает историю ваших сессий и
  предлагает, что поправить в правилах и скиллах. Сам ничего не меняет.

## Установка

Нужны Claude Code и git. Перейдите в папку проекта, который хотите подключить, и запустите:

```bash
cd ~/path/to/your-project
claude "Install https://github.com/krotghar/claude-tooling following its INSTALL.md"
```

Claude склонирует тулинг, спросит язык (русский или английский) и где держать папку данных,
подключит текущий проект и предложит настроить его под стек. Всё, что затирает или переносит
ваши файлы, он сначала показывает и спрашивает. Существующий `~/.claude/CLAUDE.md` не
теряется — переезжает в ваши личные правила.

Следующий проект подключается так же — той же командой из его папки или `/onboard-project` в
сессии Claude Code там.

**Windows:** всё работает в Git Bash, который и так ставится вместе с Claude Code. Developer
Mode не нужен: без права на симлинки `link.sh` ставит junction для папок, однострочный
импорт `@<путь>` для `CLAUDE.md` и hardlink для `.claude/settings.json`. Hardlink рвётся, когда файл
переписывают целиком (так правит Claude); повторный `link.sh` это чинит. С Developer Mode
ставятся обычные симлинки.

## Обновление

Если ставили раньше, обновляйтесь не голым `git pull`, а промптом (из любой папки):

```bash
claude "Update https://github.com/krotghar/claude-tooling following its UPDATE.md"
```

У старых установок после `git pull` глобальные правила молча отваливаются (файлы переехали),
а новые скиллы не появляются. [`UPDATE.md`](UPDATE.md) сохранит ваши правки глобальных правил
в личные, подтянет код (или предложит переклонировать, если клон старше пересоздания
репозитория), допишет недостающие настройки, перелинкует и уберёт битые ссылки. Обвязку
проектов не трогает — это копии шаблона.

## Где что лежит

Две папки:

| | Что внутри | Как обновлять |
|---|---|---|
| **Тулинг** — клон этого репозитория | общие правила, шаблон проекта, `link.sh` | `git pull` |
| **Данные** — по умолчанию `~/Documents/ai-config` | настройки ваших проектов, их вики и документы задач, память Claude, личные правила | не в git; синхронизировать между машинами (iCloud, Syncthing) или нет — на ваш выбор |

В проекте появляются симлинки на данные: `CLAUDE.md`, `.claude/skills`,
`.claude/agents`, `.claude/scripts`, `.claude/settings.json`. Они дописываются в
`.git/info/exclude`, поэтому `git status` их не показывает. Если проект сам держит в git
`CLAUDE.md` или `.claude/settings.json`, их место занимают `CLAUDE.local.md` и
`.claude/settings.local.json`.

Общие правила и скиллы обновляются сразу после `git pull`. Обвязка проекта — копия шаблона на
момент подключения: её Claude дальше дописывает под проект, и обновления шаблона сами в неё не
приходят.

## Новая машина

1. Склонировать тулинг и дождаться папки данных (если она синхронизируется).
2. Запустить ту же команду установки из папки проекта — Claude подхватит существующие данные,
   а не заведёт новые. Остальные проекты — так же, каждый из своей папки.

## Без Claude

Установщик — обёртка над `link.sh`. Его можно звать руками (на Windows — из Git Bash):

```bash
./link.sh --home                       # глобальные правила и скиллы в ~/.claude
./link.sh --init ~/path/to/project     # подключить проект: копия шаблона + симлинки
./link.sh ~/path/to/project            # перелинковать уже подключённый проект или его worktree
```

Скрипт можно запускать повторно. Настоящий файл на месте симлинка он не затирает, а
переименовывает в `<имя>.bak`.

Настройки — в `local.env` рядом с `link.sh` (его пишет установщик) или в переменных
окружения, которые главнее:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `CLAUDE_DATA` | папка данных | `~/Documents/ai-config` |
| `CLAUDE_TOOLING_LANG` | язык правил и шаблонов: `ru` или `en` | `ru` |
| `CLAUDE_PROJECTS` | папка с проектами: если задана, `--home` заодно перелинковывает их память | — |

## Если вы правите сам тулинг

Как устроен репозиторий и какие у него правила — в [`CLAUDE.md`](CLAUDE.md), почему он устроен
именно так — в [`decisions/`](decisions/index.md). Перед первым коммитом включите защиту от
утечек: `git config core.hooksPath hooks`.
