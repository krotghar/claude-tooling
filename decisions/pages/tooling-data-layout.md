## Зачем заведено

История версий нужна только нейтральной части обвязки, и эта часть должна годиться для
публикации. Данные проектов (рабочие конспекты, память, вики) истории не требуют и в
публичный репозиторий попадать не должны. Полная история решения — в журнале данных
(`$CLAUDE_DATA/decisions/`).

## Решения

1. **2026-10-28 — тулинг выделен в отдельный git-репозиторий, данные остаются без git.**
   Нейтральные файлы перенесены **копией**: старая раскладка данных продолжает работать на
   машинах, которые ещё не переехали; удаление переехавшего из данных — отдельным шагом
   после переезда всех машин. Отвергнуто: один репозиторий с данными в `.gitignore` (одна
   ошибка в allowlist — утечка); git в синк-папке; шифрованные remote (git-crypt не
   шифрует имена файлов, git-remote-gcrypt — каждый push по сути `--force`).
2. **2026-10-28 — как тулинг находит данные: переменная с дефолтом + плейсхолдеры.**
   `link.sh` читает `CLAUDE_DATA` и `CLAUDE_PROJECTS` с дефолтами. В шаблоне проекта —
   плейсхолдеры `<DataRoot>` и `<ToolingRoot>`, их `--init` подставляет вместе с
   `<Project>` (через `$HOME`, чтобы строка работала и в shell, и в markdown); хук-скрипты
   шаблона читают `${CLAUDE_DATA:-<DataRoot>}`. Отвергнуто: зашитый путь данных (личный
   путь в публичном репо); генерировать `~/.claude/CLAUDE.md` копией с подставленным путём
   (теряется симлинк и правка на месте) — в глобальном `CLAUDE.md` вместо этого описан
   `<данные>` с дефолтом.
3. **2026-10-28 — `link.sh --home` из двух корней.** Глобальные правила — из тулинга;
   личные скиллы, fish-функции и память — из данных, всё, что лежит, поштучно (раньше
   fish-функция была одна и зашита по имени).
4. **2026-10-28 — защита от утечек: allowlist-`.gitignore` + pre-commit-хук.** Общие
   паттерны (домашние пути, приватные ключи, `.lan`, RFC1918, чужой e-mail) — в репо;
   личные (имена, проекты, хосты, hostname) — в `$CLAUDE_DATA/.leak-patterns`, потому что
   список запрещённого сам по себе выдаёт то, что прячет. Хук включается
   `git config core.hooksPath hooks` в каждом клоне.
5. **2026-10-28 — синк данных между машинами — забота владельца данных,** тулинг его не
   обещает.
6. **2026-10-29 — тулинг не проектозависимый, а не обезличенный.** Владелец: email и авторство
   скрывать не нужно. Из хука убрана проверка «автор — только GitHub noreply», свой `user.email` в
   содержимом разрешён; чужие адреса по-прежнему ловятся — рабочий адрес выдаёт работодателя.
   Отвергнуто: убрать проверку e-mail в содержимом целиком. Личные паттерны имени/путей в
   `$CLAUDE_DATA/.leak-patterns` правит владелец.
7. **2026-10-31 — репозиторий публичный, лицензия MIT.** Владелец решил открыть тулинг. Перед
   переключением прогнаны общие и личные паттерны плюс поиск чужих e-mail по каждому блобу всех
   рефов, включая `refs/pull/*` (закрытые PR тоже публичны), и по сообщениям
   коммитов — чисто (совпал только свой GitHub-логин в merge-сообщениях). MIT — чтобы кодом можно
   было пользоваться; отвергнуто: без лицензии (публично, но формально «только смотреть»).
   Паттерны не поймали следы приватного проекта в истории (лежали от корня репо, а паттерны
   ищут путь проекта в данных) — они были во всех рефах, включая `refs/pull/*`.
   Поэтому старый репо переименован в `claude-tooling-old` и закрыт, а `claude-tooling` создан
   заново из вычищенной истории (`git filter-branch`); PR #1–#4 остались в старом.
   Отвергнуто: force-push одного main — `refs/pull/*` владелец удалить не может.
8. **2026-11-17 — убраны AGENTS.md-симлинки** из `link.sh` (глобальный
   `~/.agents/AGENTS.md` и `AGENTS.md` в воркtree): харнессы вне Claude Code больше не
   используются, нотация agents.md не нужна. Уже созданные симлинки убраны вручную.
   Причины заводить и подробности удаления — журнал данных, `claude-config-storage.md`.
   → пересмотрено в п. 10 (ворктри-линк возвращён).
9. **2026-11-17 — личные глобальные правила живут в данных, тулинг их импортирует.**
   Понадобилось правило, какой профиль Chrome брать для каких задач, — оно личное, а тулинг
   публичный. Глобальный `home/CLAUDE.md` заканчивается импортом `@~/.claude/CLAUDE.personal.md`,
   `link.sh --home` линкует туда `$CLAUDE_DATA/home/CLAUDE.md`, если он есть. Импорт по
   фиксированному пути в `~/.claude`, а не прямо в данные: путь к данным задаётся
   `$CLAUDE_DATA`, а в `@`-импорте переменные не раскрываются. Отвергнуто: личный раздел прямо
   в `home/CLAUDE.md` (сначала так и сделали — утечка личного в публичный репо, откатили до
   коммита); auto memory проекта (видна только в одном проекте); текстовая ссылка «прочитай
   файл» вместо импорта (грузится, только если агент вспомнит).
10. **2026-11-18 — ворктри-линк `<worktree>/AGENTS.md` возвращён; глобальный
    `~/.agents/AGENTS.md` остаётся снятым.** Со слов пользователя (2026-11-18): глобальный
    линк читал только Cline, его выпилили (вместе с `rec` и fish-функцией `pi`), а
    пер-ворктри-линк «для остальных агентов» остаётся. Пересматривает п. 8 в части ворктри.
    Отвергнуто: держать ворктри-линк снятым, как в п. 8.
11. **2026-11-18 — настройки `link.sh` — ещё и в `local.env` рядом со скриптом.** Его пишет
    инсталлятор ([[installer]]): `CLAUDE_DATA`, `CLAUDE_TOOLING_LANG`. Переменные окружения
    по-прежнему работают и берут верх. Отвергнуто: дописывать `export` в rc-файлы шелла —
    у zsh, bash и fish разный синтаксис, на Windows ещё и Git Bash. В git файл не попадает
    (allowlist).
12. **2026-11-18 — ключ памяти — от реального пути главного воркtree.** `link.sh <воркtree>`
    сам линкует `memory/<П>`, если она есть; ключ считается как в Claude Code (всё, кроме
    `[A-Za-z0-9]`, → `-`; раньше заменялись только `/._`). `--home` линкует память только
    для проектов, которые реально лежат в `$CLAUDE_PROJECTS`. Причина: у чужого пользователя
    проект может лежать где угодно, и память привязывалась бы к несуществующему каталогу.
13. **2026-11-18 — Windows — через Git Bash, без отдельного `link.ps1`.** Пользователь просил
    поддержать нативный Windows. Claude Code на Windows и так требует Git for Windows и
    гоняет Bash-инструмент и хуки через Git Bash, поэтому bash-скрипты шаблона там уже
    работают. `link.sh` под MINGW/MSYS ставит `MSYS=winsymlinks:nativestrict` (нативные
    симлинки, нужен Developer Mode; без него — ошибка, а не молчаливая копия) и переводит
    пути git `C:/...` через `cygpath`. `sed -i` убран (несовместим у BSD и GNU).
    Отвергнуто: `link.ps1` на PowerShell — вдвое больше кода, хуки шаблона всё равно на bash.
14. **2026-11-18 — скрипты шаблона без Python.** Проверка на Windows (Git Bash, Developer Mode
    включён) показала: `link.sh` работает, ключ памяти совпадает с тем, как его называет Claude
    Code (`C--Users-...`), но `python3` там — заглушка Microsoft Store. `research_edit_guard.sh`
    переписан на bash (JSON разбирается grep/sed, путь нормализуется `cd && pwd -P`), линт
    `[[ссылок]]` из `update-wiki` и `save-task-context` вынесен в `scripts/lint_links.sh`. Заодно
    починен разбор `git worktree list` в `wiki_index.sh` и хуке: путь с пробелом резался на
    `awk '{print $2}'`. Отвергнуто: требовать Python в `INSTALL.md` — лишняя зависимость ради
    двух скриптов; jq — тоже не ставится с Git for Windows. (Нормализация пути в хуке
    → пересмотрено в п. 16.)
15. **2026-11-18 — `link.sh` не ставит симлинк поверх пути, который проект держит в git.**
    Прогон `INSTALL.md` в песочнице на клоне самого тулинга: закоммиченный `CLAUDE.md` ушёл в
    `.bak`, `git status` показал typechange, а `.git/info/exclude` на отслеживаемые файлы не
    действует — симлинк на личный путь легко закоммитить. Теперь `CLAUDE.md` уходит в
    `CLAUDE.local.md`, `.claude/settings.json` — в `.claude/settings.local.json` (Claude Code
    читает их рядом с основными), `AGENTS.md` и каталоги `.claude/*` пропускаются с
    предупреждением. Симлинк прежних версий поверх отслеживаемого пути убирается, путь
    возвращается из git. `onboard-project` велит не дублировать командный `CLAUDE.md` в
    обвязке, а при `AGENTS.md` без `CLAUDE.md` — импорт `@AGENTS.md`, иначе наш `CLAUDE.md`
    его скрывает. Отвергнуто: `.claude/CLAUDE.md` как двойник — он командный по смыслу и сам
    бывает в git; линковать скиллы поштучно в отслеживаемый `.claude/skills` — лишняя
    сложность ради редкого случая.
16. **2026-11-18 — пути в `research_edit_guard.sh` на Windows — в форме `C:/x/y`.** Тот же
    прогон: `cygpath -u` превращает `%TEMP%` в `/tmp/...`, а `cd && pwd -P` — в
    `/c/Users/<u>/AppData/Local/Temp/...`, сравнение с `TMPDIR` промахивалось, и
    `bug-investigator` не мог писать в свой scratchpad (на Windows он под `%TEMP%\claude\`, а
    не `/tmp/claude-*`). `resolve` теперь отдаёт `cygpath -m`, проверяются `TMPDIR`, `TMP`,
    `TEMP`. По той же причине `link.sh` сравнивает цель симлинка через `cygpath -m` —
    повторный прогон под `%TEMP%` писал `link:` вместо `ok:`.
