# Раскладка: тулинг (git) и данные (без git)

| | |
|---|---|
| Где | `link.sh` (`TOOLING`, `CLAUDE_DATA`, `CLAUDE_PROJECTS`), `.gitignore`, `hooks/`, `home/settings.json` |
| Сейчас | Тулинг — этот репозиторий; данные — `$CLAUDE_DATA` (по умолчанию `~/Documents/claude-config`), проекты — `$CLAUDE_PROJECTS` (по умолчанию `~/StudioProjects`). `link.sh --home` берёт `home/CLAUDE.md` из тулинга, `home/skills/*`, `fish/*.fish`, `memory/*` — из данных (на 2026-10-28) |
| Связано | [[project-template]], [[knowledge-routing]] |

## Зачем заведено

История версий нужна только нейтральной части обвязки, и эта часть должна годиться для
публикации. Данные проектов (рабочие конспекты, память, вики) истории не требуют и в
публичный репозиторий попадать не должны. Полная история решения — в журнале данных
(`$CLAUDE_DATA/decisions/`).

## Решения

1. **2026-10-28 — тулинг выделен в отдельный git-репозиторий, данные остаются без git.**
   Нейтральные файлы перенесены **копией**: старая раскладка данных продолжает работать на
   машинах, которые ещё не переехали; удаление переехавшего из данных — отдельным шагом
   после переезда всех машин. Отвергнуто: один репозиторий с данными в `.gitignore` (одна
   ошибка в allowlist — утечка); git в синк-папке; шифрованные remote (git-crypt не
   шифрует имена файлов, git-remote-gcrypt — каждый push по сути `--force`).
2. **2026-10-28 — как тулинг находит данные: переменная с дефолтом + плейсхолдеры.**
   `link.sh` читает `CLAUDE_DATA` и `CLAUDE_PROJECTS` с дефолтами. В шаблоне проекта —
   плейсхолдеры `<DataRoot>` и `<ToolingRoot>`, их `--init` подставляет вместе с
   `<Project>` (через `$HOME`, чтобы строка работала и в shell, и в markdown); хук-скрипты
   шаблона читают `${CLAUDE_DATA:-<DataRoot>}`. Отвергнуто: зашитый путь данных (личный
   путь в публичном репо); генерировать `~/.claude/CLAUDE.md` копией с подставленным путём
   (теряется симлинк и правка на месте) — в глобальном `CLAUDE.md` вместо этого описан
   `<данные>` с дефолтом.
3. **2026-10-28 — `link.sh --home` из двух корней.** Глобальные правила — из тулинга;
   личные скиллы, fish-функции и память — из данных, всё, что лежит, поштучно (раньше
   fish-функция была одна и зашита по имени).
4. **2026-10-28 — защита от утечек: allowlist-`.gitignore` + pre-commit-хук.** Общие
   паттерны (домашние пути, приватные ключи, `.lan`, RFC1918, чужой e-mail) — в репо;
   личные (имена, проекты, хосты, hostname) — в `$CLAUDE_DATA/.leak-patterns`, потому что
   список запрещённого сам по себе выдаёт то, что прячет. Хук включается
   `git config core.hooksPath hooks` в каждом клоне.
5. **2026-10-28 — синк данных между машинами — забота владельца данных,** тулинг его не
   обещает.
6. **2026-10-29 — тулинг не проектозависимый, а не обезличенный.** Владелец: email и авторство
   скрывать не нужно. Из хука убрана проверка «автор — только GitHub noreply», свой `user.email` в
   содержимом разрешён; чужие адреса по-прежнему ловятся — рабочий адрес выдаёт работодателя.
   Отвергнуто: убрать проверку e-mail в содержимом целиком. Личные паттерны имени/путей в
   `$CLAUDE_DATA/.leak-patterns` правит владелец.
7. **2026-10-31 — репозиторий публичный, лицензия MIT.** Владелец решил открыть тулинг. Перед
   переключением прогнаны общие и личные паттерны плюс поиск чужих e-mail по каждому блобу всех
   рефов, включая `refs/pull/*` (закрытые PR тоже публичны), и по сообщениям
   коммитов — чисто (совпал только свой GitHub-логин в merge-сообщениях). MIT — чтобы кодом можно
   было пользоваться; отвергнуто: без лицензии (публично, но формально «только смотреть»).
   Паттерны не поймали следы приватного проекта в истории (лежали от корня репо, а паттерны
   ищут путь проекта в данных) — они были во всех рефах, включая `refs/pull/*`.
   Поэтому старый репо переименован в `claude-tooling-old` и закрыт, а `claude-tooling` создан
   заново из вычищенной истории (`git filter-branch`); PR #1–#4 остались в старом.
   Отвергнуто: force-push одного main — `refs/pull/*` владелец удалить не может.

## Пробелы и открытые вопросы
- 2026-10-28: дефолт `CLAUDE_DATA` — путь в `~/Documents` (на macOS часто iCloud). Для
  чужого пользователя тулинга это может быть неожиданно; пока оставлен, потому что
  совпадает с живой раскладкой.
