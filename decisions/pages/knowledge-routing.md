# Куда что записывать: память, CLAUDE.md, wiki, tasks, decisions

| | |
|---|---|
| Где | `home/CLAUDE.md` (разделы про память, вики задач, вики проекта), `projects/_template/wiki-CLAUDE.md`, `projects/_template/tasks-CLAUDE.md`, `decisions/CLAUDE.md`; скиллы шаблона `update-wiki`, `save-task-context` |
| Сейчас | auto memory — узнанное по ходу; `CLAUDE.md` проекта — только подтверждённое пользователем; `wiki/` — устройство проекта; `tasks/` — история тикета; `decisions/` — история обвязки: тулинга — здесь, проектов — в данных (на 2026-10-28) |
| Связано | [[tooling-data-layout]], [[project-template]] |

## Зачем заведено

Чтобы выясненное один раз не выяснять заново в следующей сессии и чтобы каждый вид
знания лежал в одном месте.

## Решения

1. **Проектная вики по методологии LLM-wiki Карпати** — вне git проекта, вне `link.sh`,
   читается по абсолютному пути. Дата — в журнале данных.
2. **Правило «сначала вики» — в глобальном `CLAUDE.md`, а не в проектном и не в хуке:**
   глобальный грузится в любой сессии, проектный в воркtree, созданные самим Claude Code,
   не доезжает. Триггер — «разбираюсь в незнакомой части проекта», а не «вопрос по
   архитектуре»: в прежней формулировке правило не срабатывало.
3. **Вики задач `tasks/`** — документ на тикет, скилл `/save-task-context`; правило «номер
   задачи → сначала документ» тоже в глобальном `CLAUDE.md`, по той же причине.
4. **Вики и задачи агент правит сам, без предложений;** `/update-wiki` — ручной рычаг.
5. **История обвязки — в `decisions/`,** а не в auto memory проекта.
6. **2026-10-28 — журналов решений два:** тулинга (этот) и данных (обвязка конкретных
   проектов + полная история до выделения тулинга). См. [[tooling-data-layout]].
