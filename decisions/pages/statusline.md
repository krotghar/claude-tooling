| | |
|---|---|
| Где | `home/scripts/statusline.sh` в тулинге → `~/.claude/scripts/statusline.sh`, подключение в `~/.claude/settings.json` → `statusLine` |
| Сейчас | `/bin/sh` + `jq` (/usr/bin/jq), префикс в стиле fish-промпта (зелёный `user@host`:синий укороченный cwd) + занятость контекста: проценты (цвет: зелёный <60 %, жёлтый 60–84 %, красный ≥85 %) и токены «X из Y»; шаблон настроек тулинга — справка по живому файлу |

## Зачем заведено
Просьба пользователя 2026-11-16: видеть в статус-баре Claude Code, насколько занят
контекст — в процентах и токенах.

## Решения
1. **2026-11-16 — скрипт в `home/scripts/statusline.sh`, а не inline-команда в settings.**
   Многострочный (форматирование чисел через awk) в inline-команде нечитаем; файл в
   data-репозитории правится без доступа к `~/.claude`. Данные передаются через stdin
   (официальные поля `context_window.used_percentage` / `total_input_tokens` /
   `context_window_size` — считать по транскрипту не нужно). Источник:
   https://code.claude.com/docs/en/statusline
2. **2026-11-16 — только контекст, без модели/директории/git/cost.** Скоуп запроса —
   занятость контекста; остальное анонсируется в футере Claude Code и дублировать не
   стали. Дорасширять при желании.
3. **2026-11-16 — добавлен прогресс-бар, метка русское «контекст» → англ. `Context`.**
   По просьбе пользователя. Бар 10 символов `▓`/`░`, ширина переопределяется
   переменной `BAR_WIDTH` — пока без конфига, правка скрипта.
4. **2026-11-16 — цветовая схема вместо порогов: занятая часть бара — зелёная,
   свободная — серая (\033[90m), текст без цвета.** Пороговые зелёный/жёлтый/красный
   отвергнуты пользователем: «зелёный на зелёном» при малой заполненности. Серый —
   ANSI bright black, читается на обеих темах стандартного терминала.
   → пересмотрено в п. 5
5. **2026-11-16 — пороги вернули, но на заполнение бара, не на текст.**
   Пользователь попросил вернуть пороговую логику; чтобы не воспроизвести
   «зелёный на зелёном» из п. 4, пороговый цвет ( зелёный <60 %, жёлтый 60–84 %,
   красный ≥85 %) красит заполненную часть бара, пустая — серая, текст без цвета.
6. **2026-11-18 — на второй машине скрипт доехал сам (iCloud), блок `statusLine` — нет.**
   Live `~/.claude/settings.json` снапшотом не переносится (см. [[claude-config-storage]]),
   поэтому при переезде на машину блок вписан в живой файл руками; скрипт уже был в
   `home/scripts/` через iCloud, работоспособность проверена прогонкой. При заведении
   новой машины — добавить блок `statusLine` в live settings вручную.

7. **2026-11-19 — добавлен префикс в стиле fish-промпта: зелёный `user@host`:синий
   cwd, укороченный как fish `prompt_pwd` (`~` вместо HOME, родители до одной буквы,
   последний компонент целиком).** Пользователь вызвал `/statusline`; PS1 нигде не
   задан (zshrc exec fish, fish_prompt не переопределял — промпт дефолтный fish),
   поэтому «из шелла» копировать нечего. Из трёх вариантов агент предложил
   (а) только fish-промпт, (б) мердж, (в) оставить как было — пользователь выбрал
   (б). Контекстный блок не тронут; скрипт и путь в settings прежние. Проверено
   прогонкой с образцом stdin.

8. **2026-11-19 — добавлено название сессии (`session_name` из stdin, пурпурный,
   обрезка до 60 символов) между cwd и контекст-баром.** Пользователь хотел
   «метку, по которой видно, что делает сессия». Не парсим транскрипт: в stdin
   уже есть готовое поле `session_name` (кастомное имя через `/rename`/`--name`
   или автозаголовок ИИ; дефолтное `my-app-3f` не попадает). Поле может
   отсутствовать — тогда блок не рисуется (грейсфул). Источник: документация
   statusline, 2026-11-19. Транскрипт-вариант (grep `type":"summary"`) отвергли,
   так как встроенного поля достаточно и он ломабельнее.
