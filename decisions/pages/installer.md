# Инсталлятор: INSTALL.md, onboard-project, tooling-review

| | |
|---|---|
| Где | `INSTALL.md`, `home/<язык>/skills/onboard-project/`, `home/<язык>/skills/tooling-review/`, `link.sh` (`local.env`, линк скиллов тулинга) |
| Сейчас | `INSTALL.md` — промпт для Claude Code, запускается из папки проекта (на 2026-11-18, п. 8): найти или склонировать тулинг (уже установлен — сразу к проекту) → проверка окружения → язык → корень данных и `local.env` → перенос существующего `~/.claude/CLAUDE.md` в личные правила → `additionalDirectories` → `link.sh --home` → текущий проект через `onboard-project` → по желанию расписание `tooling-review`. Оба скилла линкуются `--home` в `~/.claude/skills/` (на 2026-11-18) |
| Связано | [[tooling-data-layout]], [[project-template]] |

## Зачем заведено

Со слов пользователя (2026-11-18): отдал тулинг знакомому и понял, что порог входа высокий:
`CLAUDE_DATA`, `--home`, `--init`, правка шаблона руками. Нужен инсталлятор под готовый или
будущий проект, лучше ИИшный: склонировал → запустил промпт → он изучил проект или
опросил → завёл данные там, где сказал пользователь → слинковал → по желанию периодический
агент, который предлагает улучшения обвязки.

## Решения

1. **2026-11-18 — детерминированное ядро и ИИ-слой поверх.** Симлинки, копия шаблона и
   подстановки остаются в `link.sh`; ИИ задаёт вопросы, заполняет содержимое и вызывает
   `link.sh`. Отвергнуто: ИИ сам делает `ln -s` по чужому `~/.claude`.
2. **2026-11-18 — точка входа — `INSTALL.md`, а не скилл.** Скиллы появляются только после
   `link.sh --home` — курица и яйцо. Запуск: `claude "Install the tooling following
   INSTALL.md"`. Файл на английском: язык общения Claude подхватит от пользователя, язык
   шаблонов спрашивается. → запуск пересмотрен в п. 8.
3. **2026-11-18 — установка на машину и подключение проекта разделены.** Первое — один раз
   (`INSTALL.md`), второе — на каждый проект (`/onboard-project`); инсталлятор в конце просто
   читает файл скилла. → пересмотрено в п. 8.
4. **2026-11-18 — адаптация под проект — минимум.** Только «О проекте» и команды, видимые в
   файлах (манифесты, CI); вики не генерируется, остальные заглушки не трогаются. Нового
   проекта — два вопроса (что и зачем, стек). Отвергнуто: подробный опрос до первой строки
   кода (устареет за неделю) и генерация страниц вики по скану кода (банальное и
   непроверенное).
5. **2026-11-18 — синк корня данных — не забота инсталлятора.** Пользователь: цель тулинга —
   скиллы, которые упрощают работу и экономят контекст, а не синхронизация папок; многие
   работают на одной машине. Путь просто спрашивается. Отвергнуто: предупреждения про
   iCloud/Dropbox и предложение git для данных.
6. **2026-11-18 — `tooling-review` только предлагает.** Источник — транскрипты сессий
   (повторяющиеся поправки, ручные последовательности, неиспользуемые скиллы) плюс коммиты и
   память; читает их субагент. Пишет `projects/<П>/reviews/<дата>.md`; в интерактиве
   спрашивает, что применить, по расписанию — только файл. Расписание — локальное (desktop
   scheduled task или cron/Task Scheduler с `claude -p`): облачному агенту не видны
   транскрипты и данные. Отвергнуто: автоприменение (у данных нет git, откатить нечего).
7. **2026-11-18 — `.leak-patterns` инсталлятор не заводит.** Нужен только тому, кто шлёт PR
   в тулинг; знакомый пользуется тулингом для своего проекта.
8. **2026-11-18 — инсталлятор запускается из папки проекта.** Пользователь: порядок
   «склонируй тулинг, `cd` в него, запусти» странный — хочется `cd` в свой проект и
   вызвать установку там. Команда — `claude "Install https://github.com/krotghar/claude-tooling
   following its INSTALL.md"`: Claude клонирует тулинг (спрашивает куда, по умолчанию
   `~/claude-tooling`), ставит его и подключает текущий проект. Тулинг уже установлен
   (`~/.claude/skills/onboard-project` — симлинк) — сразу подключение проекта, так что та же
   команда годится и для следующих проектов; `/onboard-project` остаётся. Запуск из клона
   тулинга тоже работает — тогда проект спрашивается. Пересматривает п. 2 (как запускать) и
   п. 3 (установка и подключение — одной командой, но установка всё так же один раз).
   Отвергнуто: скрипт `curl | bash` — тулинг ставит ИИ, а не скрипт (п. 1).
