## Commands

Агенты `verifier`, `regression-checker` и `bug-investigator` своих команд не знают —
сборку, тесты, линт и запуск приложения они берут отсюда. Нет нужной команды — агент
так и доложит, а не выдумает.

```bash
<сборка / компиляция одного модуля или пакета>
<все тесты>
<тесты одного модуля или пакета>
<один тест по имени/фильтру>
<линт>
<запуск приложения и как наблюдать результат>
```

<заполнить: где лежат отчёты тест-раннера, конфиги линтера, CI, pre-commit/pre-push хуки;
что запускать только с разрешения (долгие, тяжёлые, с сайд-эффектами команды)>

## Обвязка

- Вики проекта — `<DataRoot>/projects/<Project>/wiki/` (SessionStart-хук
  `wiki_index.sh` кладёт её каталог в контекст), вики задач —
  `<DataRoot>/projects/<Project>/tasks/` (ключ задачи вида `PROJ-123`).
- Файлы `.claude/skills/`, `.claude/agents/`, `.claude/scripts/`, `.claude/settings.json`
  в git не добавлять (исключены через `.git/info/exclude`).
- Скиллы:
  - `orchestrate` — план → исполнение → проверка субагентами для задачи;
  - `check` — пользовательский `/check`: `verifier` и `reviewer` параллельно;
  - `diff-review` — inline-ревью текущего дифа, формат отчёта в `skills/diff-review/report-format.md`;
  - `commit` — пользовательский `/commit`: коммит через `scripts/commit.sh` (заголовок одной строкой, без списка и без `Co-Authored-By`);
  - `save-task-context` — документ задачи в вики задач (Claude может звать сам в конце сессии);
  - `update-wiki` — ingest узнанного в вики проекта (Claude может звать сам в конце сессии);
  - `unit-tests` — стандарты тестов, библиотеки под стек дописываются в проекте.
- Агенты:
  - `verifier` — сборка/тесты/линт по задетому, только чтение;
  - `regression-checker` — мутации: сломать код → убедиться, что целевой тест падает → вернуть;
  - `bug-investigator` — воспроизведение бага и первопричина до планирования, в своём research-воркtree;
  - `reviewer` — глубокое ревью; правила под стек дописываются в `agents/reviewer.md` проекта.

Подтверждённых конвенций пока нет — сюда только по согласованию.
