# <Project> Wiki — schema

Личная база знаний по проекту <Project>, отдельная от project
`CLAUDE.md` (симлинкуется в конкретный воркtree) и от auto-memory
(`~/.claude/projects/.../memory/MEMORY.md`). Методология — гист Карпати про
LLM-wiki (raw sources → wiki → schema, операции ingest/query/lint).

Живёт локально вне гит-репозитория (`<DataRoot>/projects/<Project>/wiki/`, каталог
данных обвязки, без версионирования). В `settings.json`/`link.sh` не участвует — это
не конфигурация Claude Code, а база знаний, которую Claude читает и пишет по
абсолютному пути, когда это релевантно задаче.

## Три слоя

- **Raw sources** (неизменяемые, здесь не дублируются): сам гит-репозиторий
  (код, история коммитов, MR), внешняя документация/вики команды, если есть,
  файл `CLAUDE.md` проекта.
- **Wiki** (`pages/*.md` + `index.md`) — то, что LLM сам пишет и поддерживает:
  саммари по архитектурным темам, entity-страницы по модулям/зонам,
  concept-страницы по паттернам (DI, навигация, работа с состоянием и т.д.).
- **Schema** — этот файл. Меняется через явное обсуждение, а не молча.

## Разница с auto-memory и project CLAUDE.md

- `project CLAUDE.md` — подтверждённые обязательные конвенции ("всегда делай X").
- `auto-memory` (`~/.claude/projects/.../memory/`) — то, что узнано по ходу
  конкретных разговоров: фидбек, контекст задач, ссылки на внешние системы.
  Короткие точечные записи, без цели быть полной картиной.
- **Эта wiki** — компаундирующийся артефакт: чем больше источников
  заингещено, тем полнее и связаннее картина архитектуры/модулей/решений
  проекта. В отличие от memory, рассчитана на рост вглубь (десятки страниц,
  перекрёстные ссылки), а не на список коротких фактов.
- **Вики задач** (`../tasks/`, своя схема `tasks/CLAUDE.md`) — что, когда и почему
  сделано по конкретному тикету, со статусами и датами. Сюда из неё переносится
  только знание про устройство проекта, верное вне задачи; в документе задачи на
  него ставится ссылка `[[slug]]`.

## Структура

- `index.md` — каталог всех страниц wiki с однострочным описанием. Читается
  первым при query, чтобы найти релевантные страницы.
- `log.md` — append-only лог операций, префикс `## [YYYY-MM-DD] ingest|query|lint | Заголовок`.
- `pages/*.md` — сами страницы. Имя файла — kebab-case slug темы
  (например `pages/di.md`, `pages/module-structure.md`).

### Формат страницы

```markdown
# Заголовок

Кратко, о чём страница (1-2 предложения).

## <разделы по смыслу>

...

## Источники
- <файл/MR/коммит/wiki-страница, из которой это взято>

## См. также
- [[other-page-slug]]
```

## Порядок работы в сессии

Вики читается **первой**, до Grep/Glob/Read по репозиторию и до плана. Правило
продублировано в глобальном `CLAUDE.md`, чтобы срабатывать в любом чате:

1. `index.md` — каталог страниц.
2. Подходящие `pages/<slug>.md` целиком.
3. Код — уже зная, куда смотреть.

Триггер — не «вопрос по архитектуре» (задачи так себя не называют), а
«собираюсь разбираться в незнакомой части проекта». «Добавь функциональность в
фичу X» под него попадает: начинать с обзорной страницы (карта фич/модулей,
если она заведена), оттуда — на страницу конкретной фичи, если она есть.

Страницы по теме нет — это не тупик, а работа: разобрался по коду → завёл
страницу (ingest). Вики компаундируется только так; сессия, в которой что-то
выяснили и не записали, потрачена наполовину.

Вики не заменяет источник истины: расходится страница с кодом — прав код, а
страницу надо поправить в этой же сессии.

## Операции

- **Ingest** — добавили источник (файл кода, MR, страницу внешней вики,
  раздел CLAUDE.md) → прочитать, выделить суть, записать/обновить
  1+ страниц в `pages/`, обновить `index.md`, дописать строку в `log.md`.
  Не переписывать всю wiki с нуля — точечно дополнять/править существующие
  страницы, если тема уже есть.
- **Query** — вопрос по архитектуре/модулям/истории решений → найти
  релевантные страницы через `index.md`, ответить с ссылками на страницы
  (и, если материал новый и ценный, зафайлить его как правку/новую страницу).
- **Lint** — по запросу пройтись по `pages/`: найти противоречия, устаревшие
  утверждения (модуль переименован/удалён), страницы-сироты без ссылок из
  `index.md`, дыры (тема упомянута, но нет страницы).

## Область данных

Только архитектура/модули/паттерны/история решений самого проекта. Не хранить
здесь: секреты, персональные данные пользователей, содержимое тикетов с
чувствительной информацией.
