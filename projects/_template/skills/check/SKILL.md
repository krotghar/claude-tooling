Пользователь попросил проверить текущую работу перед ручным тестированием. Запусти параллельно, одним сообщением с двумя вызовами инструмента Agent:

1. Субагента `verifier` — на изменённые модули текущего дифа (сборка → тесты, командами из раздела Commands в `CLAUDE.md` проекта). Линт здесь не гоняем — он нужен только перед коммитом. Regression-мутации в `/check` не входят: если задача их требует, после зелёного результата предложи отдельный прогон агентом `regression-checker`.
2. Субагента `reviewer` — на диф текущих изменений (`git diff`/`git diff HEAD`, в зависимости от того, что уже закоммичено).

Дождись оба результата, затем сведи их в один ответ:
- Статус верификации (что прошло, что нет, с деталями ошибок).
- Находки ревью (файл, строка, суть, сценарий поломки), отсортированные по серьёзности.

Если ревью нашло проблемы, требующие правок кода, — предложи их исправить, но не исправляй сам без подтверждения пользователя, если это выходит за рамки мелких точечных фиксов. Линт после правок сам не запускай: он гоняется один раз, когда пользователь попросит коммит.
