Пользователь явно попросил закоммитить с заголовком: $ARGUMENTS

Выполни ровно один шаг — вызови скрипт-обёртку, передав заголовок первым аргументом:

```
${CLAUDE_PROJECT_DIR}/.claude/scripts/commit.sh "$ARGUMENTS" ["<Имя модели> <noreply@anthropic.com>"]
```

Второй аргумент — значение `Co-Authored-By` из системной подсказки об атрибуции, и только если
`CLAUDE.md` проекта разрешает соавтора (в `scripts/commit.sh` тогда `COAUTHOR=yes`). Запрещает
или молчит — передай один заголовок. В заголовок `Co-Authored-By` не пиши.

Скрипт сам проверит формат (заголовок в одну строку, без списка изменений, `Co-Authored-By` — только вторым аргументом и только при `COAUTHOR=yes`) и либо создаст коммит, либо откажет с понятной причиной — в этом случае покажи причину пользователю и не пытайся коммитить в обход скрипта.

В рамках этого скилла не вызывай `git commit` напрямую — только через этот скрипт. Префикс задачи (`PROJ-123 ...`) скрипт не проверяет: это конвенция из `CLAUDE.md` проекта, жёсткая проверка при желании дописывается в `.claude/scripts/commit.sh`.
