# <Project> Tasks — schema

Вики по задачам проекта <Project>: один документ на задачу (тикет в трекере,
например `PROJ-123`). Цель — отвечать «что, когда и почему сделано» по
документу, не восстанавливая это по git и коду, и ссылаться на задачу номером.

Соседка проектной вики (`../wiki/`), устроена так же, но про другое:

| | `wiki/` | `tasks/` |
|---|---|---|
| О чём | как устроен проект: модули, паттерны, грабли компонентов | что делали по конкретной задаче и почему именно так |
| Единица | тема, `pages/<slug>.md` | задача, `pages/<номер>.md` |
| Состояние (статус, что проверено) | нельзя — протухает | можно, всегда с датой |
| Пополняется | `/update-wiki` | `/save-task-context` |

Живёт вне гит-репозитория (`<DataRoot>/projects/<Project>/tasks/`,
каталог данных обвязки, без версионирования), в `link.sh` не участвует, читается по
абсолютному пути. Правило «номер задачи → сначала документ» — в глобальном
`CLAUDE.md` (`~/.claude/CLAUDE.md`), чтобы работать в любом воркtree.

## Структура

- `pages/<номер>.md` — документ задачи. Имя файла = номер тикета, поэтому
  по номеру документ открывается напрямую, без `index.md`. Работа без тикета —
  slug `no-ticket-<kebab-тема>`.
- `index.md` — каталог: строка на задачу (ссылка, заголовок тикета дословно,
  ключевые слова, статус, даты), новые сверху. Нужен, когда номер не назван («та
  задача про экран настроек уведомлений»), и для обзора.
- `log.md` — append-only журнал сохранений, новые записи в конец:
  `## [YYYY-MM-DD] save | <номер> <заголовок тикета дословно>` + что
  добавилось. Отвечает на «что делали такого-то числа».

## Поиск без номера

Имя файла — только номер, чтобы не ломать ссылки и открывать документ напрямую.
По словам ищем `grep -ri '<слово>' tasks/index.md`: в строке задачи есть заголовок и
ключевые слова. Если в index не нашлось, ищем тем же grep по `tasks/pages/`.

**Ключевые слова** — одна строка, 5–10 штук через запятую: как задачу назовут
словами, не зная номера (синонимы экрана или фичи, стиль, remote-config ключ), и
главные классы и тогглы. В `index.md` и в шапке документа строка одна и та же. Это
служебные данные, их объём держим минимальным: не описание, не пересказ.

## Ссылки

`[[<номер>]]` — документ задачи (`tasks/pages/`), `[[slug]]` — страница
проектной вики (`wiki/pages/`). Пространства не должны пересекаться: номер задачи
(`PROJ-123`, `no-ticket-*`) не совпадает ни с одним slug вики. Задача без документа — простым текстом, не `[[...]]`, иначе линт
покажет битую ссылку.

## Формат документа

````markdown
# <номер> <заголовок тикета дословно, как в трекере>

Одно-два предложения: суть задачи и чем закончилась на дату последней записи.

| | |
|---|---|
| Тикет | <ссылка на тикет в трекере> |
| Ключевые слова | <5–10 через запятую, см. «Поиск без номера»> |
| Статус | <в работе / код готов / отревьюен / руками проверено / отложено / закрыто> (на YYYY-MM-DD) |
| Ветка | `<ветка задачи>` → `<целевая ветка>` |
| Коммиты / MR | необязательно: `<hash>` — <что в нём>; MR, если известен |
| Связанные | [[PROJ-456]] или PROJ-456 текстом — чем связана |
| Вики | [[slug]] |

## Постановка
Что просили, своими словами. Ссылки: тикет, макет (файл + node), доки.
Уточнения, полученные по ходу, — с датой.

## Итог
Что сделано: поведение и места в коде (модуль, ключевые классы/функции), без листингов.

## Решения
Нумерованный список: что выбрали → почему → какие варианты отвергли.
Сюда же — осознанные расхождения с макетом/легаси и решения пользователя
(«п.3 ревью не делаем — в макете линии нет»).

## Грабли и трудности
Симптом → причина → как обошли. Сюда же — ошибки и неточности самой сессии
(в том числе сказанное в чате неверно — как на самом деле).

## Осталось
Долг, непроверенное, открытые вопросы, follow-up задачи с номерами.
Закрытое не удалять молча: отметить `~~пункт~~ — закрыто YYYY-MM-DD, чем`.

## Проверка
Что и чем проверено (сборка, тесты, regression, ревью, руками) — дата и результат.

## Хронология
- YYYY-MM-DD — что сделали за сессию, коротко

## Источники
- план, handoff, макет, отчёты ревью — с датой
````

Пустой раздел — «—», а не выдуманное наполнение.

## Что писать и что нет

- **Почему важнее что.** «Что» восстановимо из git, «почему» живёт только в
  разговоре. У каждого решения — причина и отвергнутые варианты.
- **Git — необязательно.** Коммиты, пуш, MR и мерж обычно делает пользователь сам, так
  что отслеживать их не нужно. Хеш или MR известен — строка «Коммиты / MR» заполняется,
  нет — строки может не быть. Статус через «не закоммичено/не запушено» не ставим, пункты
  «закоммитить/запушить» в «Осталось» не заводим: это протухает при первом же коммите.
  Git-факт, влияющий на работу (ветка стоит поверх другой задачи, нужен ребейз), пишем.
- **Состояние — с датой.** Статус и что проверено — пишется с датой,
  на которую верно.
- **Конкретику сверять с источником**, а не с памятью сессии: имена классов,
  тогглов, путей — по коду.
- **Не пересказ переписки**, а итог: к чему пришли и почему.
- **Не листинги и не дифы** — только места в коде.
- **Не знание про устройство проекта.** Верное вне этой задачи — в `wiki/`
  (`/update-wiki`), в документе — ссылка `[[slug]]`.
- Секреты, персональные данные, чувствительное содержимое тикетов — не хранить.

## Операции

- **Save** (`/save-task-context`) — в конце сессии: создать или дополнить документ,
  обновить строку в `index.md`, дописать запись в `log.md`, прогнать линт ссылок.
  Существующий документ дополняется, а не переписывается.
- **Query** — вопрос по задаче: документ по номеру или поиском по `index.md`
  (см. «Поиск без номера»); ответ со ссылкой на документ. В документе нет ответа — идти в git/код и предложить
  дописать.
- **Lint** — по запросу: битые `[[ссылки]]`, документы вне `index.md`, статусы,
  которые давно не обновлялись.
