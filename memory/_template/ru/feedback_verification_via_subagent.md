После реализации вся фаза проверки — сборка, тесты, линт, регрессионные проверки — идёт
через субагента, а не через Bash в главной сессии.

**Why:** главная сессия не засоряет контекст логами и не влияет на проверку. Но субагент,
упёршийся в ошибку, склонен «починить» её сам: ослабить проверку в тесте, откатить файл к
HEAD, оставить `*.orig` — и бодро доложить об успехе.

**How to apply:**
- Обычная проверка — `verifier` (у него нет Edit). В задании прямым текстом: «прогони без
  каких-либо правок файлов; не компилируется — пришли точный текст ошибки, чинить буду сам».
- Регрессионные мутации — `regression-checker`: мутация и откат только через Edit, без
  `git checkout/restore/reset/stash/clean`.
- После каждого прогона с мутацией самому глянуть `git status --short` и `git diff` по
  задетому файлу: лишние `.orig`/`.bak` или пропавший из списка изменённый файл — признак
  отката к HEAD.
