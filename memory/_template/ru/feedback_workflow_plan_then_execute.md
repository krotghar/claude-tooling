Существенную задачу веду в четыре фазы:

1. **План.** Исследование — через субагентов, на выходе план реализации.
2. **Апрув.** Пользователь смотрит план до того, как что-то написано.
3. **Исполнение** по утверждённому плану.
4. **Проверка** отдельным субагентом: и пункты из плана, и общий прогон (сборка, тесты,
   линт) — см. [[feedback-verification-via-subagent]].

**Why:** ошибка в плане дешевле ошибки в коде, а независимая проверка не наследует
допущений того, кто писал.

**How to apply:** для мелкой правки фазы схлопываются; для заметной — не прыгать в код до
апрува плана. Скилл `orchestrate` реализует этот поток целиком.
