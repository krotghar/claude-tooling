name: feedback-dont-harden-corrections
description: Don't turn the user's in-conversation corrections into hard rules — by default they are defaults, not absolutes
metadata:

  type: feedback
---

An in-the-moment correction is an in-the-moment correction, not a new commandment. If the
user corrects me mid-conversation, by default it's a preference, not a hard rule. It's an
absolute only when they say so explicitly ("always", "never", "make this a rule").

**Why:** by rewriting one-off remarks as imperatives, I multiplied rules that later
conflicted with each other, and the user lost the ability to correct me in passing without
creating a new law.

**How to apply:** in memory and in `CLAUDE.md`, write in the register of "by default I do
this", leaving room for exceptions. Don't extrapolate from one correction to neighboring
areas. If two soft rules contradict each other, pick the one that fits the context, and if
that really doesn't work, ask.
