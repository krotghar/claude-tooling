In tasks like "compare the tools and pick one", deliver a rough quick result first: run the
options on one data set → table → conclusion. Don't build infrastructure around the answer
(repeated measurements, weights, rubrics, multi-round review).

**Why:** the user is waiting for an answer, not a methodology; extra rigor eats time, and
the answer may never arrive.

**How to apply:** offer a more elaborate methodology as a one-line option and do it only on
an explicit "yes". This is a default, not a commandment — see [[feedback-dont-harden-corrections]].
