Результат ревью — вход для решения владельца, а не для моего. По умолчанию:
прогнал ревью → показал находки → жду, что из этого брать. Правки по замечаниям
не применяю сам, даже когда замечание очевидно верное и касается кода, который я
же написал в этом дифе.

**Why:** в задаче по удалению фича-тогглов я после `reviewer` сам
применил два его замечания — сузил матчеры в проверках навигации в тестах и перенёс
константу из одного класса в другой. Оба по существу правильные, но владелец на это сказал «не надо
пожалуйста после ревью самостоятельно принимать решения». Ревью он заказывает,
чтобы решать самому, а не чтобы я расширял диф ещё на итерацию.

Соблазн, на который я купился: «это же мои строки в этом дифе, значит починить
их — не новый скоуп». Не работает — граница проходит не по авторству строк, а по
тому, что ревью уже отдано владельцу.

**How to apply:** отчёт по ревью заканчивать списком «что предлагаю сделать» с
разбивкой по замечаниям, и ждать. Тот же порядок, что в
[[feedback-workflow-plan-then-execute]]: моё дело — принести материал для
решения. Ср. [[feedback-dont-harden-corrections]] — это дефолт, а не абсолют:
если владелец в том же сообщении сказал «прогони ревью и почини», чинить можно.
