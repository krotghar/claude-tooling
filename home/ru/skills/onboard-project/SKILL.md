# Подключение проекта к тулингу

Цель — рабочий минимум, а не полная документация: вики и правила дорастут сами по ходу
работы. Не генерируй страниц вики и не пиши в `CLAUDE.md` того, чего не проверил по файлам.

## 0. Где что лежит

```bash
TOOLING="$(cd "$(dirname "$(readlink ~/.claude/skills/onboard-project)")/../../.." && pwd)"
[ -f "$TOOLING/local.env" ] && . "$TOOLING/local.env"
echo "tooling=$TOOLING data=${CLAUDE_DATA:-$HOME/Documents/claude-config} lang=${CLAUDE_TOOLING_LANG:-ru}"
```

Скилл запущен не из симлинка (например, его читают из INSTALL.md) — тулинг это каталог,
где лежит `link.sh`. На Windows все команды — в Git Bash.

## 1. Какой проект

Спроси путь к проекту, если его не назвали. Дальше две ветки.

### 1а. Проект уже есть

1. Это git-репозиторий? Нет — объясни, что тулинг привязывается к git-воркtree, и
   предложи `git init` (только по «да»).
2. Обвязка уже есть (`$CLAUDE_DATA/projects/<имя главного воркtree>/`) — только
   `"$TOOLING/link.sh" <путь>` и переходи к шагу 3.
3. Иначе `"$TOOLING/link.sh" --init <путь>`.
4. Изучи проект **по файлам, а не по догадкам**: README, манифесты сборки
   (`package.json`, `Cargo.toml`, `pyproject.toml`, `CMakeLists.txt`, `Makefile`,
   `build.gradle*`, `*.sln`/`*.csproj`, `go.mod` и т. п.), конфиги CI, верхний уровень
   каталогов. Большой репозиторий — отдай обзор субагенту (Explore), себе возьми вывод.
5. Заполни в `$CLAUDE_DATA/projects/<имя>/CLAUDE.md` только:
   - «О проекте» — что это, стек, основные каталоги, 3–6 строк;
   - «Commands» — команды, которые **видны в файлах** (скрипты манифеста, цели Makefile,
     шаги CI). Не нашёл команду — оставь заглушку и задай вопрос пользователю.
   Остальные заглушки не трогай.
6. Предложи одной-двумя строками, что стоит дописать под стек (правила ревьюера,
   библиотеки тестов в `unit-tests`) — без правок, по «да».

### 1б. Проекта ещё нет

1. Два вопроса, не больше: **что за проект и зачем** (одной-двумя фразами) и **стек**
   (если не решён — так и записать). Плюс где создать каталог.
2. `mkdir`, `git init`, `"$TOOLING/link.sh" --init <путь>`.
3. В «О проекте» — ответы пользователя как есть. «Commands» остаётся заглушкой — её
   заполнят, когда появится сборка.

## 2. Проверка ссылок

`ls -la <путь>/CLAUDE.md <путь>/.claude/` — симлинки на данные на месте. На Windows
симлинк должен быть симлинком (`ls -la` показывает `->`), а не копией файла.

## 3. Памяти

Покажи список из `$TOOLING/memory/_template/<язык>/MEMORY.md` — по строке на память —
и спроси, какие взять (можно «все» или «ни одной»). Выбранные скопируй в
`$CLAUDE_DATA/memory/<имя>/`, туда же `MEMORY.md` только с их строками, затем
`"$TOOLING/link.sh" <путь>` — он слинкует память по реальному пути проекта.

## 4. Итог

Коротко: где обвязка, что заполнено в `CLAUDE.md`, какие вопросы остались открытыми,
какие памяти подключены. Напомни, что новая сессия Claude Code в каталоге проекта
подхватит обвязку, а текущая — нет.
